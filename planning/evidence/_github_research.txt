- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Docker Compose v2)
- Git (optional)

## Quick Start

### Option A — One-command startup script

```bash
# 1. Clone
git clone <repo-url> vapt-saas
cd vapt-saas

# 2. Edit .env secrets (required on first run)
cp .env.example .env
# Edit .env — set SECRET_KEY and ZAP_API_KEY at minimum

# 3. Run the startup script
```

# NexCode Extension (MVP)

NexCode is a VS Code extension prototype implementing the PRD baseline plus the new **repository-persisted graph** feature.

## Implemented in this MVP

- Initial graph generation into `./.nexcode/graph.json`
- Graph rescan command for full rebuild
- Automatic graph refresh on file save (when enabled)
- Graph deletion command (`Delete Graph`) for cleanup before push
- Git mode setting:
  - `track` (default): keep `.nexcode` as commit-able repository data
  - `ignore`: auto-add `.nexcode/` to `.gitignore`
- Graph status command to verify current indexing state
- Sidebar panel in Activity Bar with one-click graph actions
- Graph-aware context preview command for write/explain prompt routing
- `write_code` flow with prompt + target path + diff preview before apply
- `explain_code` flow for active file or selection to markdown output
- `run_code` flow for active `.js`, `.ts`, `.py`, `.ps1` files via terminal

## Commands

- `NexCode: Generate Graph`
- `NexCode: Rescan Graph`
- `NexCode: Delete Graph`
- `NexCode: Toggle Graph Mode`
- `NexCode: Graph Status`
- `NexCode: Preview Graph Context`
- `NexCode: Write Code`
- `NexCode: Explain Code`
- `NexCode: Run Code`

## Sidebar

- Open the **NexCode** icon in the Activity Bar.
- Use buttons to generate/rescan/delete graph and preview context payload.
- Status card shows enabled state, graph presence, file/edge counts, and last update timestamp.

## Settings

- `nexcode.graph.enabled` (boolean, default: `true`)
- `nexcode.graph.gitMode` (`track` | `ignore`, default: `track`)

# Math Adaptive Reasoning

Empirical research project investigating whether problem-aware, confidence-aware
**adaptive routing** can improve the accuracy–efficiency trade-off of automated
mathematical reasoning compared with fixed reasoning strategies.

**Current stage: Stage 0 + Stage 1 (pilot experiment).** No classifier, router,
or verifier is built yet. We first answer a single question with a controlled
experiment:

> Do different mathematical problems benefit from different reasoning strategies?

Only a meaningful pilot signal justifies building the classifier/router.

---

## 1. Installation

Python 3.11+ is recommended.

**Fast setup on a new machine** — run the one-shot bootstrapper:

```bash
python scripts/setup_env.py                # detect, create .venv, install deps, pull models, verify
python scripts/setup_env.py --check        # detect & report only (installs nothing)
python scripts/setup_env.py --no-pull      # setup but skip model downloads
python scripts/setup_env.py --pull-math    # also pull qwen2.5-math:7b-instruct
```

It is idempotent and safe: it never deletes an existing `.venv`, existing model,
or existing files; it reuses what is already installed; and it writes reports to
`environment/` (`hardware_report.json/.md`, `environment_manifest.json`,
`setup_log.md`). It requires Python and (for model pulling) Ollama; if Ollama is
missing it prints the exact install steps and stops.

Manual install is below.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
```

## 2. Dataset preparation

The pilot uses **GSM8K** (grade-school math). Two sources are supported:

- **HuggingFace (default):** `configs/pilot.yaml` sets `source: huggingface`.
  The `datasets` package downloads `openai/gsm8k` automatically on first run
  (requires network).
- **Local:** place GSM8K-style JSONL files in `data/raw/` named like
  `train.jsonl` with `question` / `answer` fields, and set `source: local`.

The loader writes a **separate** processed subset to `data/processed/` and never
modifies the original dataset.

## 3. Model setup

This machine has **no GPU** (CPU-only PyTorch). Choose a backend in
`configs/pilot.yaml` under `model`:

| Backend | Recommended config | Notes |
|---|---|---|
| `local` (CPU) | `Qwen/Qwen2.5-1.5B-Instruct` | Free, offline, reproducible, slow on CPU. Good default. |
| `openai` | `gpt-4o-mini` + `api_key: ${OPENAI_API_KEY}` | Strong math, fast, requires key/network/cost. |
| `anthropic` | `claude-3-5-haiku-latest` + `api_key: ${ANTHROPIC_API_KEY}` | Strong math, fast, requires key/network/cost. |

The **same model** is used for all strategies; strategy is the only variable.

## 4. Configuration

Edit `configs/pilot.yaml`:

- `dataset.sample_size` — start at 100; scales to 300–500 later.
- `dataset.split` — `train` (large) or `test`.
- `strategies` — fixed set: `direct`, `cot`, `program`.
- `model` — backend, model name, `temperature`, `max_new_tokens`, device.
- `program.use_code_execution` — **off by default.** Only enable when the
  sandbox requirements (§17 guideline) are satisfied.
- `output` — directories, overwrite, and inference caching.

## 5. Running the pilot

```bash
python experiments/pilot/run_pilot.py --config configs/pilot.yaml
```

This solves every sampled problem with every strategy and writes
`results/raw/pilot_results.jsonl`. Re-runs reuse cached generations
(`results/raw/inference_cache.jsonl`).

## 🎯 Overview

**BugHunter AI** is an intelligent automated testing system that uses AI agents to play games and automatically detect bugs. The system consists of:

1. **Unity Game** - Test platformer with intentionally planted bugs
2. **Python Bot** - Autonomous AI that plays the game
3. **Bug Detection System** - Monitors gameplay and identifies anomalies
4. **Flask Backend** - API for bug reporting
5. **React Dashboard** - Real-time visualization of detected bugs

### Why BugHunter AI?

- 🚀 **Automated Testing** - No manual QA needed for basic bug detection
- 🤖 **AI-Powered** - Intelligent bot that plays like a human
- 📊 **Real-time Monitoring** - See bugs as they're discovered
- 🎯 **Multiple Bug Types** - Detects collisions, soft locks, performance issues, logic errors
- 🔍 **Evidence Collection** - Screenshots and logs for every bug

- Detailed bug viewer
